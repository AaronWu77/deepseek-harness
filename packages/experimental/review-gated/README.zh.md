# @deepseek-ai/dsh-experimental-review-gated

[English](README.md) | 中文

## 概述

在同一 RG 会话中保留需求、进度与交付，按需使用执行者和独立审查者。新建会话前，配置各角色的候选模型、默认模型与推理选项。受管一次性角色返回结构化报告，并消耗有上限的尝试次数。主 agent（智能体）可以直接工作；审查既不是交付门禁，也不授予权限。此实验性组合包需主动启用。

<a id="use-this-package"></a>
## 使用本包

### 启动前配置

通过 [Plugin Manager](../../boot/plugin-manager/README.zh.md) 将此可选组合包安装到 profile。它不在随附的官方目录中。profile 必须提供 Agent 预设注册表；Web 与 Desktop 已提供。只有 **RG** 可直接选择；**RG Worker** 与 **RG Reviewer** 仅供受管子级启动。已有安装与自动化调用请遵循[升级指南](../../../docs/upgrade-guide/v0.2.2-rc.1/rg-model-pools/guide.zh.md)。

打开 **设置 → RG 模型**，配置角色模型。选择主角色与执行者的候选模型，并为每个池选择一个默认模型。审查者可继承主角色配置，也可使用独立模型池。为每个候选配置推理选项：省略时使用适配器默认值，不继承其他角色的 effort。仅列出模型既不授权模型，也不发送模型请求。

唯一的 Host 设置条目 `rg-settings` 拥有完整的 volatile `settings` 文档。保存时，所有模型池与限制基于草稿原始修订号一起提交。Host 并发修改会阻止保存；请丢弃草稿并重新读取当前值。响应丢失不代表成功，除非 Host 镜像已包含提交的文档。切换选项卡或关闭设置时，只要 RG 客户端仍处于活动状态，草稿会保留。重连或失去设置访问权限会丢弃草稿并忽略迟到的保存结果，但不会撤销已提交的 Host 写入。如果这一情况发生在保存期间且 RG 客户端仍处于活动状态，其结果仍未知，确认已检查 Host 设置前不能再次保存。刷新失败时显示的值可能过期。卸载 RG 客户端或重新加载页面会清除这条本地警告，因此重试前请检查 Host。已保存但不可用的路由仍会显示，不会静默选择替代项。

| 设置 | 默认值 | 含义 |
|---|---|---|
| `configured` | `false` | 显式有效保存前不授权任何模型 |
| `main`、`worker` | 候选为空；无默认值 | 精确的 provider/model 模型池，逐候选配置推理选项 |
| `reviewer` | `inherit-main` | 会话创建时复制主角色配置，或使用自定义池 |
| `maxWorkerAttempts`、`maxReviewAttempts` | 各 `2` 次 | 每个人类任务、每个角色已接受的尝试上限 |
| `maxHandoffChars`、`maxReportChars` | 各 `16384` | 完整序列化交接内容／父级结果通知的字符上限 |
| `maxScopeFiles`、`maxScopeBytes` | `1024`；`16777216` | 范围检查的条目数与内容字节上限 |

保存后打开新的 RG 会话。创建时会冻结模型池、默认值、审查者继承结果、推理选项和限制；在空白会话选择 RG 时也会初始化此策略。后续设置修改只影响新会话。手动切换主模型既不改变审查者已冻结的池／默认值，也不更新全局默认模型。不符合冻结角色选项的请求会被拒绝。没有策略快照的旧 RG 会话仍可阅读，但不会自动获得授权；请新建已配置的会话。

### 本地 Git 交付

[`RgGitState`](src/git-types.ts) 声明当前本地交付状态。

使用本地 Git 交付前，请挂载 [Forge 组合包](../forge-bundle/README.zh.md)，或另行提供 worktree 服务及已有的 filesystem、subprocess、sandbox 和 sandbox-policy 服务。在 Git 检出中打开 RG 任务，在开始任何角色尝试前，让主 Agent 空闲并通过状态条明确授权仓库相对路径。此操作只授权本地任务分支和提交，不授权推送、PR、合并或远程访问。

Host 固定源检出当前已提交的 HEAD，保留主 Session 目录及其已暂存、未暂存和未跟踪的修改，并准备不复制这些修改的 linked task worktree。工作树池和共享 Git 元数据可能发生变化。普通 Git 提交钩子按继承的子进程策略运行；钩子或签名失败会停止交付提交。每个执行者和审查者交接必须覆盖完整的授权范围。执行者正式报告完成后，Host 核实实际变更并创建本地提交；新的审查者在独立 detached 检出中检查该精确候选版本。状态条显示工作树、候选提交和执行者报告的验证。重新核对会比较执行者与审查者检出和已记录的 base、head、tree 及范围标识；不匹配会使审查者报告的通过失效。这些检查依次进行，不是原子快照或写入限制：其他进程可能在检查后修改任一检出。

取消、Git 失败、中断和未知提交结果都会保留工作树、分支、索引项和提交供检查。系统不会自动 stash、reset、删除、推送或创建 PR。检查保留产物后，所有者可以明确退出本地交付而不删除产物；退出不会重置尝试预算。创建检出和提交使用当前 Session 策略，包括共享 Git 元数据的权限，绝不扩大可写根。

### 工作与审查

主 agent 可直接回答或实施，无需强制委派。仅当全部 pre-step 预处理接纳该输入后，首个直接人类任务才启动尝试计数；拒绝、空结果、取消或失败都不会创建任务，超出限制的任务在模型调用前停止，并保留原始输入供检查。可信的同进程预处理可以改写已接纳文本。澄清不会重置计数。需要为独立任务重新计数时，请在空闲状态使用状态条中显式的**开始新任务**操作。

通过 PTC，`rg_worker` 与 `rg_reviewer` 接受完整交接：目标、验收标准、精确文件／目录范围、约束、已知事实，以及验证证据或命令。每个被接受的调用先预留一次尝试，再启动不含父会话历史的全新一次性子级。该次尝试的选定模型与推理强度保持固定；每次角色请求都要求有效运行预留。重新打开已完成角色的历史不会授予新执行权限。返回子级 id 仅表示已启动。执行者报告修改、验证与未核实项；审查者报告结论、检查范围、有证据的问题、验证与未核实项。两者均通过 `run_code` 内的 `tools.structured_output` 提交正式报告。已完成角色不能接收后续工作，也不能继续委派。

同一时间只运行一个角色。结算前主 agent 对工作区必须保持只读；角色运行期间，其直接写入、编辑与命令工具会被阻止。已完成结果先写入 Session 准备记录，只有准备记录通过持久化屏障并写入匹配确认后才对外显示；确认结果保存后唤醒父级。完整结果通知（含元数据与诊断）必须满足 `maxReportChars`；超限时该次尝试失败，不保留成功报告，极小上限会缩短失败诊断。已接受尝试即使失败、取消、中断或结论不明，也消耗预算且不退还。耗尽后必须报告未解决工作；只有人类能开始新的任务预算。尝试次数上限不是 token 或费用上限。

状态条展示任务／工作版本、尝试次数、配置标识、实际上次请求模型与下次模型，以及已提交报告。审查者的通过标为**审查者报告通过**，并非已验证正确。范围变化会使其失效；依赖该结果前请使用**重新核对受审文件**或 `rg_status`。没有匹配候选版本和审查者绑定的 Git 审查显示为过期，包括相关证据暂不可用时。状态条不提供真实费用统计或费用保证。状态视图跟随 Host 已确认状态和持久历史。断线或 Session 身份不可用时，它显示不可用提示并禁用操作；未加载 RG 投影的普通 Session 也可能暂时看到该提示。读取冷历史需要 SessionQuery。进程恢复把失去运行实例的活跃尝试标为中断，而不重新启动。销毁父级或禁用／卸载 RG 会取消其拥有的角色；两种生命周期均等待子级释放和父级结果持久化结算后，才释放依赖。禁用／卸载也会阻止后续 RG 请求。结果保存失败会停止依赖工作，要求检查会话和工作区。新建任务要求 Agent 空闲且没有排队输入；请先处理待处理输入。如果新任务的保存或投递结果未知，该任务会保持阻塞以供检查；flush 失败无法确定哪些写入已经到达存储。

## 理解实现

<details>
<summary>实现细节——点击展开</summary>

[组合包补丁](cordis.patch.yml) 插入一个 Host 设置 owner 与三个基于 Persona 的预设。[运行时](src/runtime.ts) 负责冻结策略、请求授权、持久化任务预留和报告结算；已有 subagent manager 负责本地一次性生命周期与继承的 Host 权限。[角色贡献](src/role.ts) 添加带作用域的指导和主角色专用 RG 工具，不替换 Persona 或 PTC 执行器。

<a id="model-experience"></a>
## 模型体验

### 角色指导与受管报告

#### 模型看到什么

主角色收到标题为“RG: work and independent review”的 `review-gated:main` 指导、自己的 Persona，以及包含 `rg_models`、`rg_status`、`rg_worker` 和 `rg_reviewer` 的 PTC 绑定。存在保留输入时，`rg_status` 优先返回认领状态与有界文本预览，而不是普通任务事实。预览可能省略内容，flush 失败也不能保证完整输入已经写入 Session 日志。子级收到各自的 Persona、原始任务和显式交接、仅通过 PTC 报告的指导，以及角色专属的结构化输出 schema。已提交的结果通知进入主会话；启动回执不是报告。

#### Token 影响

指导与工具声明增加请求 token。交接、子级请求、结构化报告和父级结果通知按任务增加 token；使用较小角色模型不保证总用量或费用更低。

#### KV Cache 影响

Persona 与角色指导在保留的预设版本内保持稳定。交接、报告与任务历史扩展各角色的独立会话。切换主模型路由可能改变缓存复用；RG 不保证跨模型或跨角色缓存。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 审查不阻止交付，也不证明正确性。主 agent 必须披露实际验证、审查者报告的结论、检查范围与重要未核实项；允许按人类直接要求跳过审查，但必须报告。
- 审查者的只读角色对修改工作区的工具是强制执行的：在该作用域内 `write`、`edit`、`apply_patch` 与 `str_replace_editor` 均被共享工具守卫拒绝，嵌套 PTC 调用同样如此。Shell 隔离未强制执行；审查者仍可在已有 Host 沙箱下运行 `bash` 或 `pwsh`，因此由此产生的改动应视为需要审查的新工作。
- 工作区审查会在声明范围之外同时记录整个工作区的内容身份。声明范围之外的变化保持声明指纹不变、移动树身份；此时结果会说明该通过仅覆盖声明范围。树身份是信号而非门禁：工作区超过 `maxScopeFiles` 或 `maxScopeBytes` 时该项缺失并给出诊断，因此大型仓库不会因此失去全部既有通过结论。
- 指纹覆盖显式交接路径，不覆盖所有依赖，也不验证审查者所称检查范围的真实性。符号链接、不支持的文件、检查中检测到的变化或超限会产生未核实范围，绝不会产生截断后的成功指纹。检查不是原子快照：外部写入可能发生在检查之间或之后。由于文件系统元数据 API 不提供权限信息，工作区指纹不包含文件权限或可执行模式变化。没有当前版本标记的旧工作区审查指纹视为过期，需要重新审查。工作区模式不核实 linked worktree 的外部 Git 元数据。本地 Git 交付则核实其规范化链接检出和提交标识；它拒绝任一角色检出中任何位置的被忽略未跟踪文件、符号链接、子模块、二进制或非 UTF-8 修改、隐藏索引标志，以及被 Git attributes 改变的暂存内容。
- 本地 Git 交付是受信任的协作模式，不是凭据或网络边界。角色的 shell 仍可能依据继承的 Host 策略直接调用 Git 或代码托管 CLI；仅限本地的授权约束 RG 受管路径，不约束这些其他命令。
- RG 在继续依赖工作前要求该 Session 绑定的写入器成功确认。请配置支持精确 Session 绑定的持久化后端；仅有 flush 观察者不代表持久化已确认。RG 的请求准入先于 loop 追加 `user/message`，因此应挂载[会话检查点策略](../../session/session-checkpoint-policy/README.zh.md)，在适配器执行前刷新完整请求。
- 取消、中断或未确认的输入可能保持阻塞以供检查。状态视图会在可用时显示有界预览；flush 失败后，完整输入可能未写入日志。Pre-step 可能已经调用模型或工具。请检查 Session 和工作区，并仅在确认重试安全后开始新的 RG Session 并重新提交。即使先前的 flush 报告失败，重启后发现的确认记录仍可能有效。
- 受管角色要求本地 spawn，不支持 fork 或可续接 activation，也不提高 Host 配置的 subagent 深度。此组合包不会改造普通会话或授权旧 RG 会话。
