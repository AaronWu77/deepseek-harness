# Agent Note: 冻结角色授权与有界 RG 尝试

Status: implemented

[English](2026-11-08-review-gated-role-authorization.md) | 中文

## 问题

可配置的执行与审查工作流需要把模型选择归属于一次任务，而不是随部署设置或全局默认变化。选择器即使隐藏模型，也不能阻止其他请求路径选择它们。子级 id 或普通完成消息同样不能表明独立审查已针对当前文件产生有效报告。

## 决策

Review-Gated 拥有可选的业务策略。它为新 Session 捕获完整配置，包括角色候选、默认值、推理选择、限制和已解析的审查继承。通用 Session 模型策略负责精确的模型选择限制；适配器仍负责路由可用性。主 Agent 可在冻结池中切换，不改变全局默认。每次受管角色尝试绑定一个选定路由，并在请求执行时要求有效的父级／任务／运行预留记录。已完成的子级历史不构成新的执行授权。

由已有的子代理 manager 统一负责创建、取消、结构化捕获和清理。全新一次性角色预设接收显式、有界交接，而不是父会话历史。这保留独立 persona 和 PTC，也避免第二套 Agent 生命周期。接纳与清理具有不同寿命：停止新工作不能阻止已接纳尝试记录最终取消状态。父 Agent 与 RG 服务均持有已接纳工作，直到子级释放与父级结果持久化结算完成；清理失败不能跳过其中任一等待。取消权限来自有效父级引用，而非恢复的任务记录中的标识符。底层[运行所有权决策](../simplification/2026-09-17-unified-subagent-activations.zh.md)仍然有效。

任务预留在执行前消耗一次尝试，取消或失败不会退还。只有显式人类任务操作能重置计数。结构化报告要求内部捕获成功且外层 PTC 执行成功；普通子级完成不足以成立。完整父级结果文本，包括错误诊断，在保留或发送前受上界约束。超限或无效结果不能变成截断的通过报告。

审查证据包含精确工作版本，以及对声明文件范围和相关 Git 元数据的有界内容指纹。身份不可得或改变时，审查变为未核实或过期，而非保留旧通过结论。持久化预留与报告不会在重启后重放运行资源。必读事件判别值让不支持的读取器拒绝新授权数据，而不是丢弃它；兼容性审查归[持久化确认记录](../../../../docs/persistence-changes/2026-11-08-rg-model-pools.zh.md)所有。

## 考虑过的替代方案

- **使用全局模型默认，或每次调用重读配置。** 两者都会改变已有 Session 的含义，并可能在没有新的人类配置决定时扩大授权。
- **只在 UI 或模型提示词中限制选择。** 直接服务调用和默认值解析仍是执行路径，因此最终请求必须独立检查。
- **复用可续接子级作为下一次尝试。** 它会保留前次角色上下文，并掩盖新工作是否消耗尝试。全新角色保持任务归属明确；RG 之外仍可使用普通可续接委派。
- **新增 RG 专用 Agent 循环、子级 manager 或 Job 注册表。** 没有独立执行后端时，这些都会重复已有的取消和清理所有权。
- **把任何类似审查的文本视为通过，或静默保留部分范围。** 两者都不能建立报告归属或当前内容身份。

## 后果

机器强制执行授权、归属、已接纳尝试、正式报告归属与审查过期。它不建立代码正确性，不强制每次回答经过审查，不把审查者变为只读沙箱，也不施加金额预算。已有 Host 权限仍然权威。冻结策略也意味着配置编辑仅影响新 Session；中断后需要检查部分效果，而不是自动重放。

## 验证

真实服务测试覆盖替代请求路径、选定路由绑定、旧子级执行拒绝、取消计数、保存屏障及失败、插件卸载与中断恢复。已录制的 headless Session 固定全新角色 persona、仅 PTC 的请求工具、结构化报告和任务历史。范围测试保留文件内容差异并拒绝不完整身份；结果测试包含精确上界、极小上界与无效报告错误放大。
