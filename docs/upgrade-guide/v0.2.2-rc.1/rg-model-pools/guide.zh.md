# RG 模型池与受管角色尝试

[English](guide.md) | 中文

## 变更

可选 Review-Gated bundle 要求显式配置主代理与执行者模型池。除非独立配置，审查者模型继承主代理配置的冻结副本。新 RG Session 在设置编辑和重启后保留模型策略与尝试预算；选择 RG 主模型不会更新全局默认。

预设局部的 `maxReviewRounds` 设置与普通委派参数由 bundle 的 `rg-settings` 文档和结构化交接替代。执行者与审查者均为一次性调用。已接纳的失败、取消和无结论尝试都会消耗预算；完成的子级不能接受后续工作。审查是指导，不是正确性或交付门禁。

## 迁移

1. 移除旧 `rg-coordination`、`rg-worker` 和 `rg-reviewer` 工具行的自定义覆盖，使用 bundle 的三个角色贡献。更新调用 `rg_worker` 或 `rg_reviewer` 的自动化，传入结构化交接，不再使用 `description` 与 `prompt`。
2. 打开 **设置 → RG 模型**，选择主代理和执行者的候选及默认模型，选择审查继承或独立模型池，再保存完整配置。逐个候选配置推理强度；省略时使用提供方默认。
3. 新建 RG Session。没有策略快照的旧 RG Session 仍可读取，但不会获得新模型池或预算。包含新结果确认事件的 Session 需要支持这些事件的读取器；旧读取器会拒绝这些必读事件。
4. 在 RG 状态条和请求记录中核对实际角色模型、尝试计数与正式审查结论。如果先前保存的工作区审查被标为过期，请在剩余预算内请求新的审查。开始独立工作时显式新建任务；编辑设置或澄清当前任务不会重置预算。

PTC 行为、范围核对与限制见 [RG 参考](../../../../packages/experimental/review-gated/README.zh.md)。
