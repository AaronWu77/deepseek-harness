# RG 输入恢复要求使用当前 Session 读取器

[English](guide.md) | 中文

## 变更

RG 将任务准入、受保护的输入认领和直接任务准备记录为必需 Session 事件。不认识这些事件的读取器会拒绝受影响的日志。仅当全部 pre-step 预处理接纳输入后才会创建首个直接人类任务；被拒绝、为空、取消或失败的步骤不会创建任务，超限任务在调用模型前停止。中断或结果未知的输入会保留供检查，不会自动重放；flush 失败不能确定哪些记录已经到达存储。

## 迁移

1. 将读取受影响 RG Session 的所有应用或插件升级到认识这些必需事件的版本。不要使用旧读取器打开该 Session。
2. 使用能确认精确绑定写入器的 Session 持久化后端，见 [flush 确认指南](../session-flush-ack/guide.zh.md)。
3. 如果 RG 报告输入结果未知、被拒绝或为空，请在继续前检查保留的输入预览、待处理收件箱项目、Session 和工作区。完整输入可能未保存，模型或 pre-step 也可能已经执行过工作。只有确认重试安全后，才开始新的 RG Session 并重新提交。
4. 如果 RG 使用自定义 Agent 实现，请实现输入准入和受保护认领能力，或使用标准 Agent loop。开始依赖工作前，确认 RG 状态视图已连接且没有结果未知警告。
